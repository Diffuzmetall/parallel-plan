# Design sources and resolved conflicts

These are design influences, not automatically invoked or required dependencies. This package supplies its own planning contract, templates and examples. Source names refer to the inspected skills; installation-specific paths, model settings and orchestration commands are not portable requirements.

## Conflicts resolved

**Slice versus architecture:** a delivery slice is a behavior, not a required module boundary. Small public interfaces can hide deep implementations; distributing one invariant across several agents' services is not progress.

**Contract first versus working product first:** a small agreed contract can unblock consumers early. Contract-ready work is useful, but the real assembled roundtrip remains a separate acceptance claim.

**Fast testing versus realistic testing:** choose the least expensive evidence that actually exercises the claimed boundary. A fake external service is legitimate for local behavior but cannot close real service compatibility. Unauthorized live access is not a testing shortcut.

**Complete plan versus early learning:** preserve all original criteria now; detail the near-term frontier enough to execute. Refine later slices as evidence arrives instead of designing an entire imagined system or losing requirements in informal iteration.

**Parallelism versus coherence:** isolate actual independent writes and test resources; serialize the remainder. Use fewer active workers rather than invent features, split invariants or start a second scheduler.

**Universal versus heavyweight:** one executor needs a slice sequence and checks, not a team protocol. Team ownership, idle policy and milestone fan-out are conditional. None of the source workflows transfers its permissions to this skill.
